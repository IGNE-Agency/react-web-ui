## Rules

### A table is a card, part of the page

A table is a card: the card surface at a card radius, no outline and [no shadow, because it is part of the page](?path=/docs/design-system-foundation-elevation--docs#an-element-that-is-part-of-the-page-carries-no-shadow). The header is a tonal band. A nested sub-table sits on [the nested-fill tier](?path=/docs/design-system-foundation-colour--docs#surfaces-on-surfaces) so it reads as a recessed shelf under its parent row.

### Cell content is vertically centred

Cell padding is tighter vertically than horizontally, and the header gets the larger value on both axes. Cell content is vertically centred: a row's height is set by its tallest cell, and top-aligning the rest leaves chips and icon buttons floating above the text they belong to. Header cells too — a control in a header, like the page checkbox, otherwise sits on the header text's baseline. The reset unsets `vertical-align`, so every cell says `middle` for itself.

### A cell grows instead of folding

A cell is not folded. This is not an exception to [text that does not fit](?path=/docs/design-system-foundation-type--docs#text-that-does-not-fit-is-folded-never-mangled): the box grows instead, because the table is sized to its content and scrolls inside its card. Folding would let one long description drag its whole row taller than its neighbours, in a grid people read by scanning down a column. A table that needs less than the card still fills it.

### A table that scrolls sideways pins its controls, never its data

On a table that scrolls sideways, the controls you drive it with stay pinned to the edge they sit at: the leading expand and select columns to the inline start, the trailing row-action column to the inline end. Without them you scroll back to the head of the row, act on it, and scroll out again to where you were — and the action column, being last, is the one column a screen narrower than the table never shows at all. <Pull>Pin controls, never data: a pinned column is width the scrolled content no longer has.</Pull> A pinned cell has to paint its own fill, restating [the row ladder](#rows-are-striped-on-a-ladder-of-fills-mixed-from-the-tonal-container), or the rows travel through it, and the table has to collapse its borders the long way — `border-collapse: separate` with zero spacing — because a sticky cell in a collapsed-border table drifts a few pixels before it catches.

<Example kind="caution" caption="A sticky cell in a collapsed-border table drifts a few pixels before it catches.">

```scss
.table {
	border-collapse: separate;
	border-spacing: 0;
}
```

</Example>

</Beside>

### A pinned column casts a shadow while content runs under it

A pinned column can line up exactly with the columns it covers, and then it reads as one of them: the row looks whole while part of it is underneath. So while content runs under a pinned column, the column casts a faint narrow gradient onto the rows beside it, making it unmistakable that it lies over the rest of the table. It fades in as the table scrolls under the column and is absent while nothing is under it: a start-pinned column casts it once the table leaves its start, an end-pinned one until the table reaches its far end. It stops where the pinned column's cells stop. A table with no pinned column casts nothing at its edges; that the table scrolls is the scrollbar's to say.

<DoDont>

```scss
}
```

</Example>

### A nested sub-table is not a table

A nested sub-table is not a table. An expanded row's detail sits flush in the parent row's cell: no radius, no card fill, no tinted header band, so it reads as extra rows on the recessed shelf beneath its parent rather than a widget parked inside a row. Strip it by re-pointing the table's own component tokens on the nested content, [not by writing a second table treatment](?path=/docs/design-system-components--docs#each-job-has-one-component-extended-rather-than-copied).

The one inset it does take is a start indent past the control columns, so the detail begins under the first column of data. Those controls act on the parent row, and nothing in the nested table answers to them.

Size it to its own content rather than stretching it to the width of the table it sits in, where its widest column swallows the slack and the rest sit cramped beside it.

### Quantities are end-aligned, in tabular figures

A column of quantities is end-aligned, and the whole table is set in tabular figures. Amounts, counts and measures are compared by scanning down a column, and that only works when the digits sit under each other: the units column of one row above the units column of the next. Ragged-right numbers force the eye to re-measure every line, and proportional figures shift the columns even once they are aligned. Set the figures on the whole table, so dates and codes line up too. Mind that the `font` shorthand resets `font-variant`.

### A selection travels to the server as the checked ids

Whole-table selection cannot be a checkbox state, because under server pagination the client has never seen most of the rows. A selection therefore travels to the server as the list of ids the user actually checked. Where the endpoint accepts intent plus exclusions, offer an escalation to everything matching the filters.

### Rows are striped on a ladder of fills mixed from the tonal container

### Rows that are on screen never unmount

Rows that are on screen never unmount. Paging, sorting and filtering are all new server queries, and replacing the body with a spinner or an empty state on each one makes the page jump under whoever is reading it. ### A loading table is the table

A loading table is the table. That first load draws [one placeholder row per row of the selected page size](?path=/docs/design-system-foundation-motion--docs#a-wait-whose-shape-is-known-ahead-of-its-content-is-drawn-as-that-shape), so the table opens at the height it is about to have and nothing below it moves when the data lands. Those are real rows: same stripe parity, same columns.

Controls are chrome, not content. A row checkbox, an expand toggle and a row menu are on screen whether or not a row exists, so in a placeholder row they render as themselves. A column declares what it draws while empty; a column that declares nothing gets a skeleton, so data is the only thing stood in for.
