## Rules

### There is no native select

There is no native select in an app built on the kit. Its dropdown list is drawn by the user agent in the platform's own palette: it cannot take [our surface, ink, radius or highlight](?path=/docs/design-system-patterns--docs#every-popup-that-lists-things-shares-one-surface-and-one-row), and it stays stubbornly light under a dark theme. Explicit colours on an option do not reliably reach it.

### A select is labelled through the field's label prop

Label it with the field's own `label` prop rather than a `for` attribute: [the field ties its label to the trigger itself](?path=/docs/design-system-principles-accessibility--docs#every-control-has-a-name-from-exactly-one-mechanism), and an `id` given to the field never reaches the trigger, so a `for` pointed at it names nothing.

<DoDont>
<Example kind="do" caption="The component ties its label to its own trigger.">

```tsx
<SelectField
	label="Status"
	optionalLabel="optional"
	options={statusOptions}
	value={status}
	onValueChange={setStatus}
	{...selectLabels}
/>
```

</Example>
<Example kind="dont" caption="A label pointed at an id that stops at the field.">

```tsx
<label htmlFor={id}>Status</label>
<SelectField
	id={id}
	label=""
	optionalLabel="optional"
	options={statusOptions}
	value={status}
	onValueChange={setStatus}
	{...selectLabels}
/>
```

</Example>
