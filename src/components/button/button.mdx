## Rules

### A button is one of three tiers, and destructive is a tone on them

Three tiers: a solid brand fill, a tonal container, and a transparent one. Pill radius, padding-driven height, no border, [no shadow](?path=/docs/design-system-foundation-elevation--docs#a-control-never-carries-a-shadow). Three sizes. A tone that re-points the two colour tokens each tier reads, so a destructive button is the same three tiers in an error role rather than a fourth tier.

### An icon-only button is a circle, with an accessible label

### A button is a pill or a circle, wherever it sits

A button has two shapes: a pill with text, a circle when icon-only. Both are strongly rounded, and a button never takes another shape from what it sits in. A padded, rounded bar keeps its own radius, and the buttons in it stay pills.

```scss
	padding: var(--sys-unit-2);
```

### A labelled button carries an icon as well

Default to an icon on every button, not only the icon-only ones. A glyph and a word together are found faster on a dense screen than a word alone, and they tell two adjacent buttons apart before either is read.

<DoDont>
<Example
  kind="do"
  caption="A glyph beside each word tells adjacent buttons apart before either is read."
  visual={
    <div className={styles.row}>
      <Button variant="primary" icon={<Icon svg={CheckIcon} label="" />}>Apply</Button>
      <Button icon={<Icon svg={RestartIcon} label="" />}>Reset</Button>
      <Button icon={<Icon svg={DownloadIcon} label="" />}>Export</Button>
    </div>
  }>

```tsx
<Button
	variant="primary"
	icon={<CheckIcon />}
	onClick={apply}>
	Apply
</Button>
```

</Example>
<Example
  kind="dont"
  caption="A row of same-shaped word-buttons, scanned one label at a time."
  visual={
    <div className={styles.row}>
      <Button variant="primary">Apply</Button>

    </div>


</Example>
</DoDont>

<Beside>

Leave the icon off where it costs more than it gives: when no glyph means the action and an invented one is left to decode, when nothing competes for the eye anyway, as in a confirmation dialog with a single button, or when the extra inline size wraps the row.

<Example
	kind="caution"
	caption="Where no glyph means the action, an invented one is one more thing to decode."
	visual={
		<div className={styles.row}>
			<Button
				icon={<Icon svg={BubbleChartIcon} label="" />}>
				Reconcile
			</Button>
			<Button icon={<Icon svg={InsightsIcon} label="" />}>
				Allocate
			</Button>
		</div>
	}
/>

</Beside>

Density argues for adding the icon. It never argues for dropping the label: that is [the icon-only form, which comes with its own tooltip and accessible name](?path=/docs/design-system-principles-interaction--docs#an-icon-only-control-always-has-a-tooltip-and-an-accessible-name).

### A disabled button takes the disabled fill and ink

Disabled is the disabled role's pale fill with its faint ink, and [a not-allowed cursor](?path=/docs/design-system-principles-interaction--docs#the-cursor-says-what-happens-on-click). A tertiary button has no fill to lose, so only its ink fades.

<DoDont>
<Example
  kind="do"
  caption="Every filled tier goes to the same disabled fill, so nothing disabled still reads as the main action."

      <div className={styles.row}>
        <Button variant="primary" icon={<Icon svg={DownloadIcon} label="" />} disabled>Export</Button>
        <Button icon={<Icon svg={DownloadIcon} label="" />} disabled>Export</Button>
      </div>
    </div>
  }>

```scss

	color: var(--sys-color-disabled-fg);
```

</Example>

### A button whose handler awaits carries a moving indicator

A button whose handler awaits carries a moving indicator until it settles, per [every wait has an indicator, and that indicator keeps changing](?path=/docs/design-system-foundation-motion--docs#every-wait-has-an-indicator-and-that-indicator-keeps-changing). Disabling it is not that indicator, and neither is swapping its label to a present participle: both are static, so a slow request and a click that never registered look the same, and the user clicks again or gives up. The exception is a button whose [wait is already drawn somewhere the user is looking](?path=/docs/design-system-patterns--docs#a-wait-is-drawn-in-the-region-that-waits) — a row that goes stale, a placeholder that replaces the view it submitted from.

Set `aria-busy` alongside it, so the wait reaches a screen reader as a property of the control rather than as a glyph it cannot see.

<DoDont>
<Example
  kind="do"
  caption="The button carries a moving indicator until it settles, and tells a screen reader it is busy."
  visual={
    <div className={`sb-unstyled ${styles.visual}`}>
      <Button aria-busy disabled>
        <Spinner size={1} />
        Save
      </Button>
    </div>
  }>

```tsx
<Button
	onClick={save}
	aria-busy={saving || undefined}
	disabled={saving}>
	{saving ? <Spinner size={1} /> : null}
	Save
</Button>
```

</Example>
<Example
  kind="dont"
  caption="A dead-looking control either way."
  visual={<div className={`sb-unstyled ${styles.visual}`}><Button disabled>Saving…</Button></div>}>

```tsx
<Button onClick={save} disabled={saving}>
	{saving ? "Saving…" : "Save"}
</Button>
```

</Example>
