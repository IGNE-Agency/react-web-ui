# Principles

The foundation gives you the values: colours, spacing, type, shapes, states. The principles put them to use. Each one takes a handful of those values and turns them into decisions about one problem that keeps coming back, like telling two regions apart or answering a click. Components are built on both.

</Illustration>

## Each principle answers one kind of question

Find the question you're working on, and its principle has the rules. A rule that seems to belong to two principles lives on the one whose question it answers first, and the other links to it: everything you can click wears a focus ring because it answers the keyboard, so that rule lives on Interaction, and Accessibility points there.

## A principle owns no values of its own

Every principle draws on the foundation rather than adding to it. When a rule needs a value that doesn't exist yet, like a new colour, size or duration, that value goes into the foundation first, and the principle uses it from there. That's why the focus ring's look is on [States](?path=/docs/design-system-foundation-states--docs#the-focus-ring), while the rule that everything focusable wears it is on [Interaction](?path=/docs/design-system-principles-interaction--docs#everything-you-can-reach-with-the-keyboard-shows-the-focus-ring).
